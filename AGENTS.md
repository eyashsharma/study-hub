# StudyHub Telegram MTProto Streamer

## Overview
Node.js HTTP server that proxies large Telegram channel videos to a video player in 64 MB chunks via the MTProto API (GramJS / `telegram` package). No frontend — pure backend API.

## Setup
- **Runtime:** Node.js >= 18 (compose uses `node:22-slim`)
- **Dependencies:** `telegram`, `dotenv` — installed on container startup via `npm install` (no lockfile)
- **Start:** `node --watch index.js` (live reload via Node's built-in watcher)
- **Port:** listens on 8080 inside the container, mapped to host port 3000

## Required Environment Variables
All delivered via `/run/base44/app.env` (platform-managed secrets):
- `TELEGRAM_API_ID` — from https://my.telegram.org → API development tools
- `TELEGRAM_API_HASH` — from https://my.telegram.org → API development tools
- `STREAM_TOKEN` — arbitrary secret string used to authenticate API requests
- `SESSION_STRING` **or** `TELEGRAM_BOT_TOKEN` — one is required for the Telegram client to connect
  - `SESSION_STRING`: generated by running `npm run login` interactively (needs phone + SMS code + optional 2FA)
  - `TELEGRAM_BOT_TOKEN`: from @BotFather on Telegram

## Endpoints
- `GET /health` → `ok` (no auth needed)
- `GET /videos?channel=<ref>&limit=<n>&token=<token>` → JSON list of video messages in a channel
- `GET /stream?channel=<ref>&msg=<id>&size=<bytes>&token=<token>` → streams video bytes with Range support

## Notes
- The app calls `initClient()` (Telegram connection) **before** starting the HTTP server, so it will crash on startup with invalid/placeholder Telegram credentials. Real credentials are required for the server to listen.
- `login.js` is an interactive one-time script to generate `SESSION_STRING` — cannot be run in the sandbox.
